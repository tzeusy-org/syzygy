# Design

## Custody and identity

[Inferred] Treat the evaluator as a different comparison role. It supplies the frozen question-file bytes, a graded key in private custody, the synthetic run identity and one scripted reader session. The persisted answer record belongs to that evaluator's comparison run state. Place it under `benchmark/<run-id>/` in the existing dossier state root, alongside and outside the mounted operator-run directory. Never copy the graded key or private answers into the operator run's author-facing state. The companion binds the run ID, repository, pinned commit, question-file digest, graded key digest and the attributed scripted session and script digest. Earlier runs retain Unknown when no answer companion exists.

[Inferred] The program-owned synthetic fixture prepares the authoritative role views and derives the physical mount set from the same view specification using the existing role-view builder. Include read-only, writable and overriding mounts, system binds, the source checkout and the Syzygy checkout. Require exactly one prepared author, inventory, fidelity and design view. There is no editor, scout or provider path in this synthetic fixture. Do not accept an evaluator-supplied subset of arbitrary mount paths. Refuse a missing, changed or unresolved view and any overlap with the evaluator companion directory or key reads. An ordinary operator-started or live URL-supervised run does not establish this fixture custody by declaration. Always refuse links or special files at the input and output read or write boundaries. Evaluate only a complete set of unique answer rows in the frozen order. A key digest mismatch, a question/fact count mismatch, an incomplete question-file entry, a changed run binding, an unreadable companion or a screening failure refuses the dependent step with a bounded reason. No failure echoes private text.

## Answer projection and grading

[Inferred] Build the primary answer companion from validated answered or cannot-answer rows emitted through the existing scripted port. Keep literal answer or refusal text for screened, evaluator-only audit. Store the record in finite strict UTF-8 JSON. Bound the graded key to 262,144 bytes, the retained answer companion to 1,048,576 bytes and the grade record to 65,536 bytes. Read each with one bounded regular-file open and recover the exact validated bytes used for grading. The storing step returns its SHA-256 receipt to the evaluator, which keeps it outside the answer file. Exact equality with that pre-existing receipt is required before grading, including when a replacement file carries otherwise valid identities and text. The grade result binds the answer companion's SHA-256 and graded key digest so different answer bytes cannot borrow a recorded result.

[Inferred] The grader receives only a closed JSON packet of ordered, one-based question positions, answered/cannot-answer state, answer fact tokens and key fact tokens. Each fact is one nonempty LF-delimited line. Ignore surrounding ASCII whitespace and blank answer lines and deduplicate exact answer facts. The key has a nonempty unique exact fact population for each question. Assign the same positive integer to each equal fact text encountered within one question. Allocate integers in answer order and then key order, start again for every question and discard the text-to-token table when construction returns. The grader sees only the opaque equality relationships. A fixture answer that gives every required fact and no unknown fact grades right, a nonempty proper subset grades partial, and an empty answer or unknown fact grades wrong. A cannot-answer row grades refused. Report the matched and required counts with an Inferred label. The scripted shorthand measures agreement with a literal fixture key. It does not estimate a live reader's comprehension or change readiness.

[Inferred] The closed projection prevents arm identity or rendered chrome from reaching the grader as text even when present in the scripted answer. Packet construction preserves no free-form authorship identifiers. Distinct unknown strings yield the same packet when their count, order and equality pattern is the same, so a dictionary of candidate labels cannot reconstruct which of those strings occurred. An unknown inline string still makes that literal answer wrong. Keep the packet within the evaluator process.

## Independent observations

[Inferred] Test literal right, partial, wrong and refused grades including the denominator and exact reopened subject. Plant distinct arm, chrome, path, session and key-prompt canaries and check captured packet bytes for their absence. Swap only outer arm and chrome labels, then replace one nonmatching inline author cue by another, to check exact packet equality. Change the key and answer bytes independently and check the typed outcomes. Test refusal of an omitted role, an overlapping role mount, a link and unclassifiable text, then read authored fixture results again through the supported storage path. Run the ordinary provider golden and preserve every rendered byte.
