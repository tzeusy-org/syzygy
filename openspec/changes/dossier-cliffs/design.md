# Design

## Reading

[Inferred] The cliffs reuse what the rough-edge markers (v2.44) already trust: the test-name lexer blanks every comment and string interior, so a definition form runs over code text only and a constant written in a comment or inside a string yields no row; the line rule (CR, LF and CRLF, the byte-order mark dropped) and the top-level unit rule are the same functions. Each definition form is anchored to the start of its line and captures a `name` and a `value`; a name pattern decides the row's kind (timeout, threshold, limit, max, default, in that precedence). A value is kept exactly as the line writes it and typed by published value forms only (integer, decimal, boolean, string, expression of literal numbers and arithmetic, and in configuration also null and text). A value no form takes is Unknown `value-not-literal`: Syzygy never evaluates or resolves a name.

Configuration is read by two line grammars, never a parser: an ini form (`.conf`, `.cfg`, `.ini`) and a yaml subset (`values.yaml`, `values.yml`, and `config.example.*` with a yaml extension). A line outside the grammar makes the whole file Unknown `unparsed` with its fault, never read past; anchors, aliases, tags, tabs, unclosed quotes and unclosed flow collections are faults, and a sequence item is counted, not read.

## Reads

[Observed] Every candidate passes the render's screen in the rough-edge markers' disposition order (secret path, vendored or generated path, class gate, read refusal, oversize, secret-detector match, active content), so withheld configuration is Unknown with its reason and its value never reaches the page. Reads are batched 64 paths to a reader call; a refused call is re-read one path at a time, so one refusal touches only its own path. On Syzygy's own tree at `7cd5d847` this read its 1,000 source files in 16 reader calls rather than 1,000 (16.5 s against 28.7 s on this host), and the two members were byte-identical (`docs/evidence/syzygy-5dhm-116/cliffs-before-after-2026-11-28.json`). The disposition order here, in full: secret path, vendored or generated path, uncitable path, symbolic link, the path screen, the class gate, the read limit, then after the read a refusal, oversize, non-UTF-8 text, the body screen (secret detector, active content, redaction) and the grammar.

## Mutation

[Observed] Rule 6, `docs/evidence/syzygy-5dhm-116/cliffs_mutation.mjs` over the recognizer, the member, the page and the site: run 1 at `627aea0b` killed 61 of 77 (`cliffs-mutants-run1-2026-11-28.json`); fixtures were added for the survivors and nine mutants for the review repairs, and run 2 at `7cd5d847` killed 83 of 85 (`cliffs-mutants-2026-11-28.json`). The two survivors are equivalent: `non-limit-tries-next-form` (no line matches two definition forms of one language: the JavaScript forms open with `const`/`let`/`var` or with field modifiers, the C forms with `#` or an identifier) and `rows-unsorted` (candidates are sorted by path, read in that order and recognized in line order, so the sort finds them sorted).

## Limitations recorded at this version

- [Observed] Names must be upper snake case; Go's exported `MaxRetries` and Java's camel-case fields yield no row. `DEFAULT_` must begin the name, so `CONFIG_DEFAULT_HZ` yields none.
- [Observed] Under declared-source policy 2.0.0, `.conf`, `.cfg` and `.ini` have no extraction class, so those files are always Unknown `unknown-extraction-class`; the ini grammar is exercised at recognizer level only until a policy successor classes them.
- [Observed] A yaml configuration file is code content: a run with no per-project statement reads it, and a run whose statement does not list code content shows it withheld; `.env.example` is a denied path and is never read.
- [Unknown] JSON, TOML and environment-file configuration, command-line flag defaults and values assembled at run time are not read at this version; the page's note says so, so their absence from the page is not a claim that none exist.
- [Observed] A definition is read from its one line wherever it stands in code, so a Python keyword argument in a call (`MAX_CONTENT_LENGTH=16 * 1024 * 1024` in a `config.update(...)`) and a C macro inside `#if 0` are rows; a definition continued on the next line is Unknown, or not read where its form needs the line's end (Java, C declarations). The page note and the requirement say so (R-CLIFFS-1 F4).
- [Observed] An ini value continued on an indented line, as Python's configparser reads it (tox.ini, setup.cfg), makes its entry Unknown `value-not-literal`; keys indented alike under a section stay entries (R-CLIFFS-1 F2).
- [Inferred] The page fits 390 CSS pixels by its markup: every list and heading wraps anywhere and the one table sits in the shared `.table-scroll` wrapper; no browser measured `reference/cliffs.html`, because the site-wide 390-by-844 browser test fails in this environment at the base commit too (host Chrome 120, syzygy-ozo7) and its fixture holds no reference page (R-CLIFFS-1 F6).
