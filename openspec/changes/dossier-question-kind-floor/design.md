# Design

## Why a declaration and not a classifier

[Inferred] Which question a block answers is a judgement about prose. Syzygy calls no model at check, and a keyword rule over the author's text would be a claim Syzygy makes about the project's content; the author's declaration is the author's claim, labelled Inferred, and check only counts it (bead design: "The kind of a block is declared by the author in the draft and counted by check"). The replay harness uses a keyword rule only to stand in for declarations no stored draft carries, and says so in its record.

## Why the units are top-level directories

[Inferred] The bead names "the coverage plan's units"; no coverage plan has landed (pursuit move R4 slice 3 is unbuilt). The nearest derived units are the facts of rule `top-level-unit` that check already derives from the pinned tree's listing, with no body read: paths and modes alone, every secret-matching path left out and never named. A directory holding at least one twentieth of the listed files is major, at most eight, so a tree's `.github` or `examples` does not draw six advisories. A block answers for a directory when one of its citations names a path inside it, and every declared block answers for the whole repository. When a coverage plan lands, its units can replace rule `major-unit` under a new rule version.

## Why the member adds no schema number

[Inferred] Version 2.12 set the precedent: a member that is optional, never rendered and read by no gate is inert, and a schema that gains it keeps its identifier while its file digest changes. `questionKinds` meets each condition. A new number would also have to say how it joins the reserved v11 and v12, which version 2.26 forbids v13 to absorb.

## Regression rule

[Inferred] `CONTRIBUTING.md`'s comprehension-regression rule applies, because the brief and the draft schema change. No stored draft carries `questionKinds` and no renderer changes, so every stored run renders the same bytes before and after; the effect of brief v21 on a new run is Unknown until one is made.

## Limits of rule `major-unit` version 1

[Inferred] Rule `top-level-unit` lists the first 250 directories by name, not by size, so a large directory past that point is never major; `unitsNotListed` counts what it left out. A monorepo's `packages/` or `apps/` is one unit, so gaps per package are invisible. Every declared block answers for `.`, so its `missing` is the weakest signal. The share of one twentieth and the cap of eight are a first choice, made so that a tree's small support directories draw no advice; neither is calibrated, and a coverage plan's units would replace both.
