Candidate version 2.18. This amendment extends the reader rule of REQ-polaris-generation-034 version 2.10 to the run-tree files of REQ-polaris-generation-033, -035 and -048, each under a stated bound. It composes over the effective text of each (033 after version 2.17, 035 and 048 after version 2.1) and binds by its agent adoption and version tag.

Governed and non-governed subjects receive the same admission rules.

Since version 2.18 every reader of a run file this requirement states SHALL read it by the reader rule of REQ-polaris-generation-034 version 2.10, under a bound stated here, since the run directory lies within the agent sessions' write reach: it opens the path once, without blocking and following a symbolic link; refuses, without reading any byte of it, anything whose opened descriptor is not a regular file (a directory, a device or a FIFO) or gives a size larger than the bound; and reads from that descriptor at most one byte more than the bound, a file of which it reads more than the bound being past it. The files and their bounds are: the run record, `run.json`, 65,536 bytes; the step log, `steps.jsonl`, and the adapter-credential breach log, `credential-breaches.jsonl`, 16,777,216 bytes each; the credential list the run's credential probe reads, 65,536 bytes; the owner's execution choice, `execution-choice.json`, 8,192 bytes; and the close record, `record.json`, 16,777,216 bytes. Each is a bound of the readers, not one derived from the file's writer: every reader of `run.json`, of the execution choice and of the close record already parses it under that bound, so a larger file is already none it can use, and the probe already refuses a credential list past it from its size; the two logs gain a line at every step and every breach with no cap, and their one reader, close, carries at most their first 10,000 lines. Every reader of `run.json` reads it so: each step's reverification and its step-log append, check, render, `syzygy dossier status`, the recheck of a session's declared provider, the reading ledger reading the other runs of its state root, and the URL supervisor taking the run's repair-cycle limit. A reader takes a file that is not a regular file or is past its bound as a file it cannot read, and gives the outcome it gives today for a file at that path that cannot be read. Where the outcome a reader gives today for a file at that path that cannot be read names the failed read's error code, it names `not a regular file` or `larger than <bound> bytes` in its place, `<bound>` being the file's bound in digits without separators. So the reverification refuses with `record-invalid` and `<run> holds no readable run.json (not a regular file)` or `<run> holds no readable run.json (larger than 65536 bytes)`, and `syzygy dossier status` with the same words, `<run>` being the run directory as each names it today; the execution-rule reader refuses the choice with `execution-choice.json cannot be read (not a regular file)` or `execution-choice.json cannot be read (larger than 8192 bytes)`; the credential probe refuses the list with its existing words, `<file> is not a regular file` or `<file> is larger than 65536 bytes`, now also for a list grown after its size was taken; close carries no instants from such a step log and no entries from such a breach log, as for a log it cannot read; status gives the agent usage of such a close record as `not recorded; the Execution Record cannot be read`; the reading ledger counts such a run among `unreadableRuns`; a step appends no step-log entry, as when it cannot read the run record today; and the URL supervisor takes such a run record as declaring no repair-cycle limit, as it takes one that does not parse, while the reverification refuses every step it runs on that run. No reader of these files blocks on its path, reads more than one byte past its bound, or exhausts its memory on a device. A regular file within its bound is read exactly as before, so version 2.18 changes no byte that any step writes or renders for one; it changes only the outcomes and words above, for a file that is not a regular file, is past its bound, or grows past it while it is read.
