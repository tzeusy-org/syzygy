## Which specification owns the inventory check record

[Observed] No requirement states the inventory check record's form or how it is read. REQ-polaris-generation-035 (`polaris-dossier-local-agent-mode`, signed off) hands the check of the inventory to REQ-034: "Syzygy SHALL check its quotations and citations as REQ-polaris-generation-034 checks a draft". REQ-034 already names the inventory check record in its own text (figure fit, the reading ledger and the manifest facts each say "an inventory check record carries none"), and `inventory-check` runs the same `checkSubject` as `check` with the inventory's plan (`check.ts`, lines 50 and 220 to 312; `inventory.ts`, lines 278 to 321). Its readers are two: `inventoryOfRecord` (`inventory.ts`, line 365, through `readRecord`, `run-dir.ts` line 74, bounded at 262,144 bytes, 4,096 values and 8 levels, read whole before the bound is tested) and the supervisor's `latestChecks` (`polaris.ts`, lines 679 and 682, `readUnbounded`, `JSON.parse` with no bound). A sweep of `packages/polaris-dossier/src` and `apps/three-surface-poc/src` outside tests for `INVENTORY_CHECKS`, `inventory/checks` and `INVENTORY_CHECK_FORMAT` finds no other reader.

[Inferred] So the owning text is REQ-034, and this version amends it. A code-only fix is not enough: the bound is observable. Under it a planted record past the bound stops counting with a stated reason, and the supervisor no longer stops on it; and the raise from 262,144 bytes and 4,096 values changes which passed inventories count (below). REQ-035 is not amended; it joins REQ-034's parent requirements, since this version's readers decide whether its inventory counts.

## (a) The rule chosen, and why

[Inferred] Options considered:

1. Cap each member (quotations per draft, cited files, withheld ranges). Rejected: four or five new caps, each a new finding the brief must explain, and the redaction member would need a cap on withheld ranges that screening, not the author, produces; the sum would still need measuring against the bound on every change.
2. A more compact encoding (paths once, no pretty print). Rejected: it changes every record's bytes and format and still leaves the redaction ranges unbounded.
3. Raise the read bound again. Rejected: no bound covers the redaction case, and every reader holds the record in memory.
4. Measure the record before writing it and, past the bound, write a bounded form with one finding (chosen). It bounds every record whatever member grows and whatever the cause, keeps every record Syzygy writes readable by every reader (so the supervisor's repair-cycle stop and the end screen see the revision), fails closed with a repair finding the author can act on (quote and cite less), and changes no byte of any record within the bound. Its cost: a draft whose full record would be past the bound does not pass where version 2.9 called it passed and then could not read it; that is a correction, not a loss.

[Inferred] The bounded form keeps the members whose size Syzygy, not the subject, determines. It drops `manifestFacts` too, though 2.8 bounds it below 10,000,000 bytes, so that the bounded form's size is one small figure rather than a sum that depends on 2.8's measurement holding; no reader takes manifest facts from a stored record (version 2.7), and version 2.9's maps re-derive them at render. It drops `executionFlags`, which a draft with schema findings can make as large as its `executions` array. The full findings go to check's report as `findingsLeftOut`, written to no file, so the author keeps every finding to repair from.

## (b) "No derived record was kept" told apart from "kept but unusable"

[Observed] `derivedStructureAt` (`derived-record.ts`) returns `missing` with `missing-evidence` both where `readDerivedRecord` finds no file and where it finds one it refuses (line 176), and again where the record names a rule, version or path the render does not derive (line 192); the region's words for `missing-evidence` are one string, `no derived record was kept when this draft revision was checked` (`dossier-site.ts`, line 998). The record is read under the screen and Syzygy version of the render (the screen and currency policy are read at the Syzygy checkout's HEAD), so a record check wrote is refused when the screen now matches one of its directories as a secret path, or a later rule version derives other units; 2.8's design recorded this as residual F3 and kept the words to avoid moving bytes.

[Inferred] Chosen: the reason code stays `missing-evidence` in both cases. RFC2-24 is closed at twelve reasons, and #2, "Declaration exists; no current evidence artifact for the claim", resolved by "Produce/capture evidence" (checking the draft again writes a new record), describes both; #4 `stale-beyond-currency-bound` would say the evidence exists and is merely old, which a refused record does not establish, and draws nothing. The words split on one observable fact, what examining `derived/rev-<n>.json` without following a link reports: no such entry, or a parent that is not a directory, keeps the 2.9 words; anything else, an entry of any kind that is no readable record or an error that leaves it unknown whether one is there, gets `this draft revision's derived-record path holds something this render cannot use or cannot examine; Syzygy or its screen may have changed since the revision was checked, or the path may have been altered`. The words say neither "file" (a directory, a FIFO or a device may stand there) nor that Syzygy wrote it, because the run directory is within the agent sessions' write reach and a planted entry reads the same; they name the causes as possibilities. The render reads the record by the check-record readers' rule (open once without blocking, regular file only, at most one byte past the bound), under the derived record's own 4,194,304-byte bound, so a FIFO or a device there neither hangs nor exhausts the render. The machine view's `state` splits the same way (`missing` and the new `unusable`), so both channels carry the distinction (VIS-2; RFC6-14's parity is on the reason, which both keep). The decision order stated in the spec is `derivedStructureAt`'s order today.

## Bytes this version changes

[Inferred] Written: a draft or inventory check record whose full form would be past the read bound (its bounded form instead); that check's report (`findingsLeftOut`; no `figureFit`, `mechanismAdvice` or `readingLedger`); `run-advice.json`, which counts the bounded form as read where version 2.9 counted an oversized record as unreadable; the step log's findings count; and the close record's digests of those run files. Rendered: for a run whose inventory record lies between today's 262,144-byte or 4,096-value bound and the read bound, every downstream artifact that now proceeds; for a render whose derived-record path holds an entry that is no readable record, the region's sentence on `index.html`, the directory map's sentence on `maps/directories.html` (version 2.9 gives it the region's words), `derivedStructure.state` and `computedMaps.directories.state` (`unusable`), the size report's measures of those two pages, and the rendered-design packet. Unchanged: every check record within the bound, every other render's pages and machine view, the brief, the draft and inventory schemas, and every provider-mode byte.

## What the code must change

[Inferred]

- `packages/polaris-dossier/src/check.ts`: after building `stored`, encode it once and measure bytes, values and depth (as `parseBoundedJson` counts, through an injectable measure so tests reach the value and depth arms) against `CHECK_RECORD_LIMITS`; the step log counts the stored record's findings; past any, write the bounded form (members as the spec lists, `outcome` `findings`, one `check-record-bound` finding with the counts) and put the full findings on the report as `findingsLeftOut`; the 2.9 report fields that read `stored` (`figureFit`, `mechanismAdvice`) are absent then, and `readingDifference` is computed with no ledger. Both subjects, since `checkSubject` writes both.
- `packages/polaris-dossier/src/check-model.ts`: the finding kind `check-record-bound`.
- `packages/polaris-dossier/src/inventory.ts`: `inventoryOfRecord` reads the inventory check record through a size-first reader under `CHECK_RECORD_LIMITS` (as `readCheckRecord` does), not `readRecord`; a refusal keeps the reason `the result of inventory revision <n> cannot be read`.
- `packages/polaris-dossier/src/polaris.ts`: `latestChecks` reads the inventory record under the same reader; `readUnbounded` and its default argument go.
- `packages/polaris-dossier/src/check-record-read.ts`: replace `readCheckRecord`'s `statSync` then `readFileSync` (lines 14 to 16), which a symbolic link to `/dev/zero` passes with size 0 and then reads until memory runs out (the review's probe aborted with `std::bad_alloc`), and on which a FIFO blocks: open once with `O_RDONLY | O_NONBLOCK` (following links), `fstat` the descriptor, refuse anything not a regular file or past the bound, read at most bound + 1 bytes; one reader for both formats, and the same rule, with the 4,194,304-byte bound, for `readDerivedRecord`.
- `packages/polaris-dossier/src/derived-record.ts`, `packages/polaris-generation-core/src/local-render.ts` and `apps/three-surface-poc/src/polaris-generation/dossier-site.ts`: `readDerivedRecord` tells "no entry" (`lstat` fails with `ENOENT` or `ENOTDIR`) from everything else; `derivedStructureAt` returns `unusable` for the latter and for a foreign record; the `LocalDerivedStructure` state union gains `unusable`; the region's words are chosen by state, not by reason; the machine view and `computedMaps.directories.state` carry the state.
- Compatibility with the 2.9 code being written in parallel (which touches `derived-record.ts`, `render.ts`, `dossier-site.ts`, `check.ts` and `reader-advice.ts`): its `run-advice.json` writer must read each check record through the size-first reader, and must count a bounded form as read with no `figureFit` (its "Unreadable check record in the run file" scenario already treats a record without `figureFit` so); its directory map takes the region's words, so it inherits the new sentence with no change of its own.
- Tests: records just within and past the byte bound for both subjects, and the value and depth arms through the injected measure; a symbolic link to `/dev/zero`, a FIFO, a directory and a file grown after `fstat` at a check record's and at a derived record's path, each refused without blocking; a draft with findings past the bound and its `findingsLeftOut`; inventory records of 262,145 bytes and 4,097 values that now count, and of 16,777,217 bytes refused before any byte is read (as `check-record-read.test.ts` does for drafts), by both readers, with the supervisor neither proceeding nor stopping; a derived record refused under a changed screen, one removed, and a directory at its path, asserting both sentences and states; goldens of records within the bound and of the provider mode unchanged.
