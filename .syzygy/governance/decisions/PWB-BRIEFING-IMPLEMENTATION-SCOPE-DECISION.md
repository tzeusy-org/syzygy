# Scope decision for implementing the Polaris machine briefing

[Observed] `syzygy-bivj` is the separate scheduling gate for `syzygy-dov.5.2`, M5 slice 3. PWB-REQ-020 names `GET /api/poc/briefing` as a derived read-only machine view. The machine-view act says the briefing remains unservable until its ceiling is declared and the route is separately authorized. The 2026-09-30 read direction preserved that gate. The M2 slice 5 continuation recorded in PR #492 expressly excluded the route and its ceiling read from that continuation. Those records retain their original scope. [PWB-REQ-020](../../../openspec/changes/polaris-project-wide-butlers-model/specs/polaris-project-wide-butlers-model/spec.md) · [Machine-view act](PWB-MACHINE-VIEW-AMENDMENT-ACT.md#what-this-act-does-not-authorize) · [September read direction](OWNER-INSTRUCTIONS-2026-09-29-30-READABILITY-AND-REGISTRY.md) · [M2 slice 5 continuation](PWB-M2-SLICE-5-IMPLEMENTATION-CONTINUATION-DIRECTION.md)

**Decision.** On protected landing with its VIS-4 adoption row, this decision satisfies the separate implementation authorization for `syzygy-dov.5.2` within the boundary below. VIS-4 assigns implementation scheduling to agents and allows an adoption to satisfy the equivalent lower-rule gate. The implementation bead still requires fresh dispatch admission, available shared-model WIP, and independent review of its own behavior. Its current source custody is outside this decision. [VIS-4](../doctrine/vision.md) · [SEC-5](../doctrine/security.md)

## Inherited boundary

- Keep one exact project-shape claim as the briefing subject, identified by its full claim ID. Every served value comes from the existing machine answer at the same evaluation. Verify derivation against that answer's actual bytes with a checker that imports no rendering code. The complete existing machine answer remains served in full under its own ceiling. The briefing adds no project fact and writes nothing. [PWB-REQ-020](../../../openspec/changes/polaris-project-wide-butlers-model/specs/polaris-project-wide-butlers-model/spec.md) · [RFC6-21](../contracts/rfcs/RFC-0006-cross-surface-selection-query-drawer.md)
- Require the existing machine credential on every mount. No new source, body or target repository reads, retention, credential scope, screening exception, provider admission, network exposure, deployment or release follows from this decision. SEC-5 continues to exclude matching and unclassifiable content. [PWB-REQ-020](../../../openspec/changes/polaris-project-wide-butlers-model/specs/polaris-project-wide-butlers-model/spec.md) · [SEC-5](../doctrine/security.md)
- Use the effective declaration's `maxBriefingResponseBytes` of 20,480 for the final encoded body. It is independent of `maxMachineResponseBytes`. A missing or unverified declaration leaves the route unservable. Overflow returns only the bounded typed failure required by the declaration, with evaluation and limit identity, declared and observed values and population counts. No partial success is served. PWB-REQ-021 readiness is false for the breach. [Registry declaration](../declarations/adapter-registry/POLARIS-BUTLERS-PROJECT-SHAPE-OBSERVER-CANDIDATE.json) · [Effective digest binding](PWB-OBSERVER-REGISTRY-MACHINE-CEILING-ACT.md)

## Evidence the implementation must supply

The implementation review needs independently reproducible comparisons against the actual same-evaluation machine-answer bytes, including an absent claim and a value available only at another evaluation. Exercise missing and valid credentials in every supported mount, and establish that the complete machine answer is still available. Measure final encoded bytes with a valid declaration at the limit and one byte over. Also exercise an absent or unverified declaration. Check the recorded failure and readiness and the lack of source or write calls. These checks belong to `syzygy-dov.5.2`. This decision carries no endpoint or verification result.
