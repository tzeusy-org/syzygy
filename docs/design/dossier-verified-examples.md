## Opening example

[Inferred] Let a later operator-agent draft select one optional opening example with the existing code excerpt's citation and language hint. A short extract of a command session, documentation transcript or code can work when its actual source lines let a new reader recognize what the project does. The title and thesis introduce the subject. The existing graph or recorded omission leads their following region. Place the example immediately after that graph or omission and before later overview figures and descriptions. A graph gives the opening map and the example gives the next concrete thing to read. This proposes an example adjacent to the existing hero. Literal placement directly after the thesis would change the adopted order and belongs in the shared P3 landing composition.

[Inferred] Keep the example static, with its visible epistemic marking and source link together and one descriptive heading. Follow the same order in the DOM and on narrow screens. A withheld excerpt occupies its expected position with the existing plain-language Unknown notice and only the policy-permitted details. When the example is absent, the overview flows directly from the existing hero or omission to the rest of the overview.

Use the code-element path and range verifier and renderer for this placement and for the walk below. Obtain the displayed text from one 1–60 line citation in a screened blob at the pinned revision. Render admitted text byte for byte as inert text and give its Observed label a recomputed RFC7-10 artifact-and-byte-range anchor. Apply source-scoped admissions, the existing no-body-read rule for paths excluded before reading, and the existing rules for malformed, missing and out-of-bounds citations. An excluded, invalid UTF-8 or redacted span renders Unknown with `excluded-content` and the appropriate existing withheld treatment. An excluded path the policy bars from naming contributes only its permitted count. Keep submitted withheld ranges marked as agent-supplied and unverified where displayed. Scope text examples to files that are already within the run's allowed source set. Commands and output in a file are depicted as source text. [Effective REQ-034](../../openspec/changes/dossier-containment-figure/proposed/polaris-generation/spec.md), [RFC7-10](../../.syzygy/governance/contracts/rfcs/RFC-0007/narrative-contract.md), [SEC-3 and SEC-5](../../.syzygy/governance/doctrine/security.md).

## Annotated code walk

[Inferred] A produced deep dive can carry a walk made of one such excerpt and an ordered list of one or more margin notes. Each note names an inclusive range in the source blob's own line numbering contained within the excerpt's submitted range. This range places the note. Each margin note is a distinct Inferred claim block with its own citations, checking, provenance and fidelity entry under REQ-polaris-generation-035. Place the ordered notes after the preformatted source text so a keyboard or narrow-screen reader follows the same sequence as a wide-screen reader.

A missing note, malformed or reversed note range, or range extending beyond the excerpt is a repair finding at that walk or note. When the excerpt is withheld, note positions are agent-supplied and unverified. Apply the ordinary claim screening and withholding rules independently to every note. A note relying on an excluded source stays subject to that rule even if its range lies within the submitted excerpt. An admitted independently cited note can still render with its own Inferred label and verified citation anchor. [Historical P5 proposal](../../.syzygy/governance/contracts/candidates/polaris-dossier-local-agent-mode-v1-7/SEMANTIC-DELTA.md#p5--show-then-tell), [effective REQ-034](../../openspec/changes/dossier-containment-figure/proposed/polaris-generation/spec.md).

## Author advice

[Inferred] A separately reviewable author-advice change can look for a selected code element in the existing eligible produced sections and deep dives and suggest one example when none is selected. Under a future opening-example version, that example also counts as a selection. Count at most one absence per eligible draft. A graph by itself does not supply a source example. Selection is a structural fact about the draft. It does not establish verification or exhaustive coverage, and the advisory never tells a reader that a withheld excerpt means a project lacks examples. Use report-only placement in the existing check command. Keep the check record, findings, readiness, and render byte-identical for a matched run with the advice disabled. Before a new schema feature is available, any versioned brief guidance asks authors to use the existing code element and cite the selected range. Allocate reader-standard and brief version identities only in the future reviewed change. [Reader advice implementation](../../packages/polaris-dossier/src/reader-advice.ts), [brief implementation](../../packages/polaris-dossier/src/brief.ts).

## Acceptance scenarios for a future change

| When | Then |
|---|---|
| An eligible draft supplies an admitted opening example, a produced overview graph and another figure | Show the graph first after the header, followed by the Observed example and its intact source link, then the other figure. The DOM and visual order agree at mobile and desktop widths. Use a separate fixture where a reasoned omission leads and the example follows. |
| The same eligible draft omits the opening example | Its existing graph or omission leads, then the other figures or content. Compare the established hero witnesses and the current hero's machine record. |
| The fixture includes CRLF, Unicode and HTML metacharacters, and the working-tree text or a saved range is altered after check | The pinned blob and independently computed byte range supply matching displayed source text and anchor. The HTML metacharacters remain inert. Agent-authored replacement text and a modified stored range cannot supply an Observed excerpt. |
| The citation is missing, malformed, reversed, over 60 lines, outside the admitted blob or names a non-blob path | Check reports the existing case-specific repair finding. Use one-line and 60-line successful controls and a 61-line refusal. Separate an out-of-range admitted source from a pre-read exclusion where the end check is withheld. |
| The source path is excluded before any body read, or the fixture body is excluded or invalid UTF-8 | Show Unknown with `excluded-content` and no excluded content, source-page route or disallowed path. A read counter confirms pre-read exclusion. The displayed submitted range, if present, remains agent-supplied and unverified. A checked body-end refusal after a read does not reveal the excluded body or its length. |
| An admitted synthetic body has a screened line inside the submitted excerpt | Withhold the whole selected excerpt and its source anchor. Apply the existing screened-source policy to other, admitted spans of the retained body. |
| A deep dive selects code with two correctly cited notes at the excerpt's first and last lines | The excerpt has its own Observed source anchor. The ordered list follows it in the DOM and renders each note as its own Inferred claim with its own citation, provenance and fidelity entry. Literal fixture line positions supply the oracle. |
| A walk has no notes, an invalid placement range or a placement range whose apparent citation is its only purported evidence | A case-specific repair finding identifies the failing walk or note. A withheld excerpt with an independently supported note retains the admitted note and discloses the unverified placement. A note relying on withheld material uses the existing claim withholding path. |
| A supported draft has neither a qualifying visible code selection nor a supported opening example field | One check-report advisory offers the example. An ordinary produced code element clears it, a graph alone does not clear it, and an element only in a non-produced part gives no visible selection. Compare outcomes, finding census, durable records and render bytes with the advisory disabled. |
| A stored pre-feature draft or provider-mode report enters check and render | Replay the preserved historical behaviors and golden provider bytes. A future schema-version boundary rejects new fields on old schemas under the existing field-version convention. Test any independently adopted report-only advice against its exact declared versions. |

Use synthetic Syzygy-owned fixtures for these scenarios. Record both outcomes of the rule-6 controls for pinned-source reuse, incorrect range acceptance, screening and withheld rendering, missing or uncited note, false note placement, old-schema field admission and advice leaking into readiness. At acceptance, check exact fixture denominators, ordinary operator-agent and provider paths, and legacy rendering. Evaluate new copy and order with text, source links and keyboard reading sequence at both widths.
