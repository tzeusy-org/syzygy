# Lexical import evidence for dossier checks

[Inferred] A dossier author could use a report of which package units mention other units in source import statements. The report would give the rule and the admitted source location for each match. This candidate design for `syzygy-3efd.60` scopes the check report to two initial language cohorts and defines what a partial result means. A later reviewed specification would bind the behavior.

## Report scope

[Inferred] Add a sibling assessment to the operator-agent check report. For the first version of each cohort, the assessment would take the full, strictly decoded bytes of files already admitted at the pinned revision by the existing dossier flow. The admission must bind the actual path and body to that revision, policy, content class and run outcome. The existing cited-blob ledger records a redacted body as admitted with a redaction field. Require affirmative whole-body screening, class eligibility and an ordinary blob mode at the scanner entrance. A supplied span, a redacted body, withheld or refused bytes, invalid text, a symbolic link, a submodule or a non-file object therefore leaves the input Unknown. The recognizer receives only admitted bytes and the safe, pinned unit index. Source selection uses the existing admission and read ceilings. Repository code, build files and resolvers are data throughout. [Current citation-body handling](../../packages/polaris-dossier/src/check-derive.ts).

[Inferred] Each reported statement names its cohort rule and version, the admitted source path and closed line range, and the source and target package-manifest identities. It states that the recognizer matched an import declaration at that location and resolved its literal under the cohort's bounded path rule. A statement with no distinct target unit still contributes to the assessment's matching or unresolved counts as applicable. The unit graph groups admitted statements by exact ordered source and target identities, retains the contributing locations, and uses stable order over identities and locations. Matches and unit edges remain Inferred. Repeated statements may share one edge. Positions are computed from the admitted file, and literal contents are screened again before any derived label or path is emitted. Refused paths, raw import strings and refused target identities stay out of the report.

[Inferred] Resolve the source to the closest uniquely identified enclosing package manifest in the existing unit index. Resolve the lexical target within the pinned tree and the cohort's explicitly supported paths, then require that the matching file belongs to a unique admitted target unit of the same cohort. For either endpoint, require affirmative proof that the allowed address choices are complete for that decision and have exactly one usable outcome. Hidden or unevaluable candidates make that endpoint Unknown whenever they could change it. A package's declared dependency, label or familiar project name cannot supply a missing import destination. The language labels and exact line range describe the source statement alone.

## Initial cohorts

[Inferred] Start with TypeScript under the existing `.ts` source admission. Recognize complete static import declarations with a literal relative specifier, including side-effect and type-only declarations. Keep type-only as lexical provenance. For this cohort, resolve an explicit `.ts` target or an extensionless path with exactly one of the declared `.ts` and `/index.ts` forms under the pinned repository root. The importer's directory supplies the starting path. Escape above that root, multiple address matches, package aliases, runtime `import()`, CommonJS `require`, import assignment and re-export syntax are outside this first grammar. Tokens in comments, strings and templates are ignored, and a body the grammar cannot delineate safely yields Unknown.

[Inferred] Stage Python after the TypeScript evidence is accepted. Recognize one explicit absolute dotted module operand of `import` or `from … import`. In the `from` form, the operand before `import` is the target module. A selected member or alias adds no target. For this cohort, the existing `pyproject.toml` units contribute the declared directory and its literal `src` child as the only supported roots. Match an exact dotted path to either a module file or a package initializer, with an initializer at every supported package prefix. Prove uniqueness across the admitted candidate roots and complete address choices. Relative imports, namespace packages, computed lookup, external modules and search-path changes fall outside this cohort. Text in comments and quoted strings, including triple-quoted strings, produces no statement. Malformed bodies yield Unknown.

[Inferred] Give each cohort its own recognition rule, fixture inventory and mutation record. TypeScript can complete its own review while Python remains unevaluated. A cohort with no complete evidence carries its limited result or Unknown even when another cohort passes. Each later expansion needs its own reviewed grammar, bounded resolution and evidence. Scope the work to the operator-agent check report. Authored edge states continue to follow A-64's relation rules, and provider rendering is bound to the existing golden bytes.

## Coverage and refusal

[Inferred] Count every distinct known candidate file in the pinned admission population exactly once. Assign it **scanned** when eligible input has completed lexical analysis of the declared grammar, **incomplete** when eligible analysis started and did not complete, or **unavailable** when eligible scanner input was missing. The known count equals scanned plus incomplete plus unavailable. Where admission permits only an aggregate for denied or budget-limited inputs, carry that aggregate at its existing scope. Mark the full denominator or remainder Unknown wherever lawful metadata cannot establish it.

[Inferred] For each recognized statement, report target resolution independently as an admitted edge, a confirmed same-unit match, or Unknown. Show identifiable unsupported forms as outside the assessed grammar. A scanned file can produce both an admitted edge and an Unknown target and still counts once under scanned. Complete safely resolved statements survive an incomplete file where their lexical span and admission were established before the interruption. Where a path or output value cannot be safely screened, use the existing permitted aggregate or a generic Unknown reason. A zero of matched statements names the exact assessed grammar and input scope. A report with unavailable input, incomplete analysis or Unknown targets states its coverage limit separately from its known counts.

## Acceptance scenarios for a later specification

| When | Then |
| --- | --- |
| An admitted TypeScript file in one manifest unit contains a static relative import into a different uniquely resolved TypeScript manifest unit, and a second location carries a type-only import of the same unit | The literal fixture gives one ordered unit edge with two exact locations and the separate type-only marker. Rule, version and source line boundaries match the fixture. |
| The corresponding admitted Python fixture names a dotted module in a distinct unit, and another `from` statement names that module plus an imported member | Python yields the literal ordered pair and two locations. The member creates no additional destination. The Python result has its own rule and record. |
| Genuine imports are accompanied by matching text inside TypeScript line or block comments and strings or templates, or Python comments and strings | The complete output holds only the genuine statement locations. Controls move one supported statement at a time entirely inside these contexts. |
| A safe import has more than one visible address, an unsupported form, or a module outside the supported unit index | The result reports Unknown or outside the assessed grammar as applicable and carries the corresponding limitation. A safely analyzed complete fixture with no recognized statement has an exact zero for its declared scope. |
| One eligible file completes lexical scanning of two distinct statements. The first has one uniquely resolved target unit. For the second, a withheld candidate could change target resolution | The file ledger is one scanned, zero incomplete, zero unavailable. The statement results are one exact ordered edge with the first location and one Unknown at the second location. The withheld identity is absent and the report marks target coverage partial. |
| Two records share the same `admitted` state. The first has affirmative whole-body admission. The second carries a redaction marker on the otherwise equal input | The whole-body case invokes the scanner. The redacted case invokes it zero times, occupies unavailable, and publishes only its permitted refusal information. |
| A matched statement has one fully admitted address and the relevant address set is complete. A paired fixture adds one hidden candidate address that could also match, holding the original usable address fixed | The complete fixture emits the one edge. The paired fixture remains scanned and supplies one Unknown target and no edge. Its public record withholds the hidden identity. |
| The file input is withheld, malformed, over the current bound or unreadable, or a candidate path or output value fails the existing screen | Incomplete lexical work and unavailable input stay distinct from a scanned zero. The known file population balances once per candidate. The denominator is Unknown where permitted evidence cannot establish it. |
| The TypeScript cohort has passed its checks and Python remains staged | TypeScript reports its own results, Python reports that it was unevaluated, and the combined report gives no all-language absence or completeness claim. |
| The draft authors an `imports` arrow, or the existing manifest recognizer emits a dependency declaration | The draft keeps its existing witness disposition, including `no-witness-rule` where reached. A dependency declaration creates no lexical match. Provider render bytes match the unchanged golden. |
