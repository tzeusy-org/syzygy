# PWB extraction grammar diagnostics

Candidate for `syzygy-lx69`. This design would add an optional diagnostic report for the exact input already admitted to project-shape extraction. Diagnosing an arbitrary working tree from an operator command remains an open part of the Bead.

## Diagnostic report

[Inferred] Build the report within the same bounded traversal of the same admitted bytes and loaded grammar. Preserve the canonical extraction result exactly, including the first-failure selection in grammar declaration order, its reasons, all items and their order, Unknown denominators, sibling status, and the readiness projection. Diagnostic ordering is independent of the canonical failure selection, which retains the predecessor's predicate precedence even when a different diagnostic has an earlier physical line.

The optional diagnostic is private and report-local. Within an otherwise admitted evaluation, retain at most 64 findings across the requested classes. When a 65th supported finding exists, retain the first 64 in diagnostic order, declare the affected coverage partial, and set the fixed reason `diagnostic-cap`. Exactly 64 findings alone do not trigger that reason. The cap bounds only the private finding collection and cannot charge another parse pass, alter registered evaluation limits or prevent the canonical extractor from completing. Exposing an operator output, traversing again, or writing a new durable record needs the applicable registry and normative review.

The diagnostic never survives an adopted read, parse-work or whole-evaluation resource refusal. Preserve the exact whole-source and whole-evaluation typed refusals where they apply, with dependent facts Unknown and no diagnostic prefix at any final sink. A final-response ceiling breach keeps the existing bounded typed refusal only. A refusal can leave independently admitted siblings in the canonical result where the existing rules already allow that distinction. A separate reason inside the private diagnostic is never evidence of an adopted resource breach.

The report is tied to the already-admitted source revision and grammar identity in its existing caller context. The optional report itself carries requested class, coverage state, and a list of typed findings. Each finding carries an existing extraction failure code and, when the extractor can identify an exact source position, a one-based line. Use the established line model. Emit ordered findings by declared class, then physical line and the declared predicate order for equal positions. A positionless reason is ordered before positioned findings of its class. If independent faults have identical allowed fields, preserve their multiplicity. No finding exposes raw failure detail, heading text, declaration/key names, source snippets, absolute paths, or a new locator.

Coverage states apply separately to each class.

- **Complete** means every declared grammar check is assessable on the admitted bytes and inspected under the budget, including already established malformed units that leave neighboring boundaries unambiguous. A complete diagnostic may have findings. An empty complete diagnostic does not assert zero items.
- **Partial** means some declared checks yield reliable findings or inspections, and other declared checks remain Unknown. Keep only independently supported results. If a missing or ambiguous heading prevents identifying child units, report the proved root failure and leave its dependent units Unknown.
- **Unknown** means the operation has no trustworthy class grammar or readable admitted input, or cannot start within its budget. Its diagnostic findings are absent. The pre-existing canonical failure or refusal remains available through its current path.

Use the declared grammar's actual record boundaries. Continue after a malformed list item or table row only when the parser can locate the next admissible boundary without guessing. For TOML, report the parser's typed failure and leave unchecked dependent entries Unknown if the grammar cannot delimit them after that fault. A duplicate is reportable only where the same declared comparison key is reliable on both records. Unenumerated headings stay outside the assessed population. An incomplete report states its coverage state even when it has no findings to show.

A future operator lint may consume an already-admitted diagnostic projection or use a separately reviewed input contract. The requested arbitrary-worktree lint remains open. Its own source selection, ownership and screening, permitted read operations, registry charges, unavailable-input behavior, output cap and re-fix verification require a reviewed [CC-REV-2](../../.syzygy/governance/contracts/candidates/policy-candidates/NORMATIVE-CHANGE-WORKFLOW.md) decision before an implementation can read anything on its behalf. This candidate specifies no new source admission, local or network side effect, project class or policy outcome.

## Paired acceptance controls

Use fictional inputs in the ordinary extraction entry and compare the full canonical result with diagnostics enabled and disabled. Require exact equality for canonical results, including refusals, as well as the expected optional diagnostic result.

| Control | Required observation |
| --- | --- |
| Two ambiguous leading labels at physical lines 5 and 6 in one declared principles list, with a valid success-criterion sibling | The canonical first failure is line 5, the principles denominator is Unknown and only the success-criterion item exists. The complete principles diagnostic has two `ambiguous-leading-label` findings ordered 5, 6. |
| Fix only line 5, then fix line 6 as well | The first change leaves a single finding at 6 and a failed canonical class. The second leaves a complete empty diagnostic and two admitted principles. Sibling disposition and existing charge sequence stay the same. |
| Remove the required heading, keeping the same orphaned lines and sibling | The canonical class fails with `missing-heading`. The partial diagnostic retains only the proved positional-less root finding. Its children are Unknown and the sibling remains complete. |
| Put the second malformed-looking row behind a recognized inert fence or outside declared headings | The independent row contributes no diagnostic finding, with closing fences and the existing unenumerated disposition preserved. |
| Present a duplicate-looking pair with one unparseable comparison key | Report the proved malformed record. If its key cannot be read, dependent duplicate comparison stays Unknown. Repair only the malformed record to the same valid key as its sibling and require the exact declared duplicate failure. |
| Break a TOML construct before a visually plausible later key whose boundary the grammar cannot establish | Preserve the existing canonical failure. Publish only independently established findings and partial coverage for the failed class. |
| Withhold the body, refuse profile or exhaust the existing bound before the first declared pass | Keep original Unknown/refusal and proof of no additional read or charge. The optional report supplies no findings for the unavailable class. |
| Deny the second declared parse after the first contains a known fault. Repeat with an admitted second pass and with the final response ceiling independently breached. | The denied pass yields the exact whole-source over-limit result and no diagnostic prefix. Permitting it yields the original partial canonical result and eligible diagnostic. Final encoded response refused by the adopted ceiling contains only its existing typed envelope. |
| On an otherwise admitted evaluation with the same canonical output and charge sequence, vary the private capacity around the exact 64 and 65 independently supported findings. | For 64 the report has 64 findings and no cap reason. For 65 its first 64 in diagnostic order coincide with the uncapped fixture's independently enumerated prefix, the affected coverage is partial and the fixed reason is `diagnostic-cap`. The canonical result and readiness equal the diagnostic-disabled run. |
| Two reliable duplicate keys appear at lines 3 and 4, followed by a different late ambiguous leading label at line 5 and a valid sibling class. Deliberately replacing the canonical winner with the lowest diagnostic line fails the original oracle even in an otherwise identical disabled run. |
| Place a distinct high-entropy fictional marker in each malformed heading, key, raw detail and line | Verify through the enclosing report writer and final bytes that the output retains only the closed diagnostic fields and never copies the marker. |
