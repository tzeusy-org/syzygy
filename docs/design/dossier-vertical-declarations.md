## Inventory and draft

[Inferred] A versioned inventory form can propose up to twelve candidates. Each has an inventory-local identity, a short name, a scope paragraph and one or more existing path-and-line citations. Candidate names and scopes are Inferred authoring evidence. Keep the inventory produced and checked in its existing independent session. Its candidates inform the draft and fidelity review. The inventory brief asks the independent session to look for top-level package and service boundaries, document headings, spec directories and entry points in already admitted evidence. These are discovery cues. The inventory contributes no renderable body or route directly, and a match between the two documents does not establish a vertical as Observed.

[Inferred] The future supported draft form has a `verticals` record with at most twelve entries. Each entry has a draft-local stable identity, a short name, one scope paragraph, one or more existing pinned path-and-line citations, and one decision with a reason. The three decisions are `expand`, `cover` and `skip`. They mean that the author proposes a sub-dossier, has assigned coverage within the parent, or has decided to omit additional coverage for the stated reason. A `cover` entry names the parent section that addresses it, validated against the draft's own produced sections. Identity and row order are for traceability and review. Scope and reason are Inferred. Neither the inventory nor the draft supplies a child URL.

[Inferred] An assessed empty set is represented explicitly with the author's reviewable explanation. It states the assessment in this draft. The denominator for the repository's actual feature verticals stays Unknown. A missing, unsupported or withheld declaration state follows the existing draft layer's treatment. The brief explains these states, the reviewer's comparison with independent candidates and the fact that a decision to expand is a plan. The adoption decides the exact field and brief versions after the predecessor composition is fixed.

## Check and fidelity

[Inferred] Check uses the frozen draft record as the sole source for declared identities, decisions and expansion totals. It rejects a duplicate or malformed identity, missing citation, invalid decision or reason, unmatched `cover` section, or more than twelve declarations. It rejects an `expand` total over the effective `verticalLimit` recorded for that run. A newly configured run defaults to six in the absence of an explicit bound. Count validly declared expansion decisions before applying source visibility to the rendered rows. If a retained run needs the bound and its effective value is unavailable, check refuses. The run supervisor owns the declaration and lifetime of that bound. A depth-2 expansion guard belongs to `syzygy-ea4w.2.2`.

[Inferred] Use existing pinned path-and-range checking, source admission, screening and withheld treatments. The check reads only sources it could already cite and read. A structurally missing or invalid citation remains a named repair finding. A row supported only by screened-out sources is withheld through the existing claim rules, with only policy-permitted metadata. Screen draft-authored names, scopes and reasons through the existing claim-body rule even when the citations are admitted. The row's identity, authored name, scope, reason, excluded bytes and secret-matching paths do not appear in rendered output, link labels, indexes or outward diagnostics. A withheld row still contributes to the check's expansion bound where its decision is valid. A visible mixed-evidence row follows the existing withheld-count and provenance rules, with no secret-matching path. An entirely withheld draft supplies no declaration output. The independent fidelity review accounts for supported draft entries, divergent inventory candidates and assessed-empty explanations using the existing frozen-subject and review rules.

## What the parent shows

[Inferred] Draw one ordered list in draft order in a standalone feature-verticals section of the parent. This section can ship with the declaration capability. When the `syzygy-ea4w.1` coverage map is available, it associates that same section with pillar 5, whichever change lands first. Each visible entry shows its name, scope, decision and reason beside its evidence marking and citations. A `cover` row can link to its admitted local section. A `skip` row keeps its reason and needs no child link. An `expand` row describes a proposed expansion while the child is unavailable. Where the sibling delivery supplies a verified association to a rendered child at the same pinned revision, the parent can link to that child. The declaration renderer consumes that association. Run creation, depth enforcement, child URL allocation, breadcrumbs, status and spend belong to `syzygy-ea4w.2.2` and `syzygy-ea4w.2.3`. A reason text, section name or display title never supplies link authority.

## Acceptance for the later change

| When | Then |
| --- | --- |
| An independent inventory proposes two cited candidates and a supported draft takes three explicit decisions | Check counts three draft decisions in their original order and the fidelity packet ties its inventory comparison to the existing subject identities. Neither inventory titles nor decisions that are absent from the frozen draft appear by implication on the parent. |
| A draft has twelve valid rows, then a matched fixture has thirteen | Twelve rows admit. Thirteen produce the row-limit finding. Use separate fixtures for a missing citation, duplicate identity, missing reason, unrecognized decision and a `cover` whose target is absent or unproduced. Each independently fails at the affected declaration. |
| A newly configured run uses its default, and drafts declare six expansions and then seven | Six admit and seven produce the expansion-limit finding. With an explicit limit of two, use the separate two/three control and use a source-screened row in the paired fixtures to verify its valid decision still counts during check. A retained run whose effective bound is unavailable refuses. |
| An allowed row cites a path withheld before its body is read, or its only relied-on span is withheld after reading | The body-read counter distinguishes the two cases. The operator-facing rule shows the existing Unknown treatment and exposes none of the hidden draft text or source bytes. A paired admitted fixture retains its own supported citation. A wholly withheld draft contributes no declaration rows or links. |
| A parent contains `cover`, `skip` and `expand` rows, and one scoped child was rendered | The feature-verticals list follows draft order, preserves reasons and shows only links supported by an admitted parent section or a verified child association. A pending expansion, a child at another revision and a route absent from the rendered site have no child link. Use literals for expected labels, link targets and row count. |
| The declaration capability renders before the full pillar map, then the same record renders with that map | The first parent has one standalone feature-verticals section. The second has one section with the same declaration rows and a pillar-5 mapping to that section. Reversing which capability lands first yields the same mapped result. |
| A supported draft contains an explicit assessed-empty record, then an older draft without the feature is replayed | The first renders its scoped explanatory state and leaves the project denominator Unknown. The older draft follows the previous behavior; a new field submitted under its version receives the existing field-version treatment. Compare the prior provider render bytes separately. |

Use Syzygy-owned synthetic fixtures. Keep literal expected row counts and evidence markings independent of the validator. Record repaired and reverted outcomes for the citation, bounds, duplicate-identity, withheld-output and wrong-child-association predicates. The full acceptance needs the versioned REQ amendment and adoption record, the standalone parent renderer and check behavior, and separately verified sibling integration where a child is available.
