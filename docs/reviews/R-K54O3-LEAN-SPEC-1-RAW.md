## Findings

1. **blocking** — The effective specification after A-340 contradicts itself on a SEC-5 ingest gate, and 2.46 does not say why that is lawful.
   [Observed] The effective 033 (identical in `dossier-step-measures`, `dossier-question-file`, `dossier-scripted-benchmark-grading` spec.md line 11) still says: "URL acquisition SHALL follow REQ-polaris-generation-047's memory-only complete-admission-before-write gate … no owned raw-clone spool or partial-source fallback is permitted", and line 29 "protected source-operation admission/attempt/send/outcome captures under025/047". The effective 2.1 035/048 cite 025's relay, canonical receipt and inert-view receipt (2.1 spec lines ~154–170, 409–417 cite "under025", "025's independent canonical receipt"). 2.46 removes every one of those referents, and its own 047 prescribes the raw-clone spool 033 forbids. 2.46's retained 025 also keeps "Before every ingest into any store … the observing project's own committed secret policy SHALL be applied" and "every governed-content transmission … SHALL pass the single declared-provider … check", while its 047 `git fetch` writes unscreened objects to a Syzygy-owned directory and sends to an undeclared source host (design.md D4 admits: "a one-commit fetch writes git objects before any screen").
   [Inferred] This is covered by doctrine D11 (SEC-2/SEC-5: the dossier session's raw-clone reads are the owner-accepted exception), but no file in the package cites D11 (`grep -rF D11 openspec/changes/dossier-url-lean-run/` → 0 hits), and GOVERNING-DEPENDENCIES lists only D10. Without that warrant, removing the all-admitted gate reads as an unrecorded weakening of secret screening, which is owner-class.
   Fix: (a) add D11 to both requirements' `decisions` warrants and say in 047 that the one-commit clone is the raw clone of SEC-2's D11 exception, outside 025's ingest boundary, and that a `git ls-remote`/fetch to the repository's own host sends only the URL and an advertised identifier (not governed content), so 025's provider check does not apply to it; (b) add a "Dangling references" section to SEMANTIC-DELTA listing every effective 033/035/048 sentence that now cites a removed 025/047 clause (at least the two 033 sentences above and the 035/048 relay/receipt sentences), each marked as a known gap owned by `syzygy-k54o.3.4`. If D11 is judged not to cover a Syzygy-made clone, this goes to the owner.

2. **should-fix** — 047 says the trunk is pinned without `--revision`; with `--clone` the code pins the clone's HEAD.
   [Observed] `setUp` (polaris.ts 446–458): with `--clone` and no `--revision`, `chosen = { label: clone-…, commit: <clone HEAD> }`, with no comparison to the remote HEAD. 047 says "Without `--revision` the pin SHALL be the commit the remote's advertised HEAD names at this launch (trunk)" with no `--clone` exception. And "init SHALL check that its HEAD is the pinned commit": `init` gets no `--revision` from `setUp` (line 481). The check is `setUp`'s and only runs when `--revision` is given; otherwise it is tautological.
   Fix: "With `--clone`, the pin SHALL be the clone's HEAD; when `--revision` is given, Syzygy SHALL refuse unless it names that commit (a full commit compared with no network, a name resolved by anonymous `ls-remote`)." Move the HEAD check from `init` to the supervisor, or pass `--revision` to `init` in code.

3. **should-fix** — The visibility and refusal SHALLs over-state the code under `--clone`.
   [Observed] "A repository that answers an anonymous `git ls-remote` SHALL be declared public": `operatorCloneIsPublic` returns true only when the clone's commit equals the remote trunk, so a public repository's clone at any other commit is declared private (polaris.ts 433–436). "A URL that does not answer an anonymous `git ls-remote` SHALL refuse, naming `--clone`": with `--clone` and no name to resolve, an unreadable URL is not refused; the run proceeds as private. Both behaviours are the intended conservative ones.
   Fix: scope both sentences to the no-`--clone` path, and state the `--clone` rule: public only when the clone's commit is the anonymously advertised trunk, else private.

4. **should-fix** — The scenario "Operator's clone" and the Case row "`--clone` (… elsewhere)" have no outcome that matches the code for "elsewhere" without `--revision`.
   [Observed] Such a clone is accepted and pinned at its own HEAD (finding 2). Fix: add a scenario for a clone at a non-trunk commit, saying it is accepted, pinned there and declared private, plus a refusal case for `--revision` naming another commit.

5. **should-fix** — The no-match refusal text does not do what 047 says.
   [Observed] 047: a name that matches no reference "SHALL refuse, asking for a full reference or commit". The code (polaris.ts 422) returns "`<url>` has no branch or tag named X" and asks for 40 characters only when X looks like abbreviated hex. Fix: either word the SHALL as "SHALL refuse, naming the reference" or append "; give a full ref or full commit" in code. The scenario's "naming the resolving action" is vague; an oracle cannot fail it. Quote the expected words.

6. **should-fix** — "no stored credential … SHALL take part" / Falsifier "any … operator configuration taking part" is wider than `anonymousGit`.
   [Observed] `anonymousGit` passes `HTTP(S)_PROXY`/`NO_PROXY` through (polaris.ts 362–365). A proxy URL can carry user information. The `--clone` HEAD read runs `git -C <operator clone>`, which honours that repository's local config. Fix: state the proxy pass-through and the repository-local config as disclosed exceptions, or strip user information from proxy values.
